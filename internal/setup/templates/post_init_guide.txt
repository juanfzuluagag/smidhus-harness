We have successfully initialized the Smidhus Harness.

--- Post-Init Quickstart Guide ---

1. Review the Blueprint (.harness/blueprint.md)
   Read it to ensure the technology stack and rules are correct, or manually add any necessary technical constraints.

2. Configure your Agents (.harness/agents.yml)
   Open this file to set the AI models for each role.
   - Architect & Builder: Assign high-reasoning models (e.g., gemini-2.5-pro, qwen-max).
   - Designer, Cloud & Documenter: Fast models work great (e.g., gemini-2.5-flash).
   - Gatekeeper: Needs good logic to audit the builder's code.

3. Define your Tasks (.harness/state/tasks.json)
   This is the brain of the workflow. Write your tasks here. The orchestrator will pick the first "pending" task and start the Spec-Driven development cycle.

4. Visual Mockups for the Designer
   If a task requires UI implementation, drop an image in .harness/specs/ and name it exactly like your task ID (e.g., T003_mockup.jpg). The Designer agent will see it and code it.

Next step: run 'smidhus-harness run' to start forging.
